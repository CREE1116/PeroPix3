# PeroPix 3.0

[English](README.md) · [한국어](README.ko.md) · **日本語**

NovelAI 画像生成のためのデスクトップ作業台です。**シーンレーン**に場面を並べて一括で回し、
プロンプトは**ブロック**で組み立てて**カード**として使い回します。

Tauri 2 + React 19（フロントエンド）+ Python FastAPI（バックエンド、サイドカーとして起動）。

## 必要なもの

- **NovelAI のサブスクリプション**と **Persistent API Token**。画像を作るのは NovelAI で、
  このアプリはその手前に立つ作業台です。トークンは NovelAI のアカウント設定で発行でき、
  `pst-` で始まります。初回起動時に**設定 ▸ 一般**から入力してください。
- 生成には **Anlas** がかかります。プランの無料条件（解像度・ステップ数の上限）に収まる
  画像は 0 で、生成ボタンがそのつどの金額を表示します。
- **Windows 10/11。** WebView2 ランタイムが必要ですが、通常はすでに入っています。

## 入手して使う

リリースの `PeroPix-<バージョン>-win64.zip` を展開し、`PeroPix.exe` を実行します。

- **インストーラーではなくポータブル版です。** `data/`・`workspaces/`・`logs/` を
  **実行ファイルの隣**に書き込むため、書き込みできる場所（ドキュメントフォルダーや
  別ドライブなど）に展開してください。Program Files に置くと初回起動で止まります。
- Python は同梱されています（`python/`）。別途インストールする必要はありません。
- **複数を別々に展開して同時に使えます。** フォルダーごとにポート・保存先・設定が分かれます。
  同じフォルダーを二重に起動することだけを防いでいます。
- 移動も削除も**フォルダーごと**で構いません。レジストリには何も残しません。

## 何がどこに保存されるか

すべて `PeroPix.exe` の隣です。

| 場所 | 中身 |
|---|---|
| `workspaces/<名前>/` | ワークスペース — タブ・シーン・プロンプトと `output/` の生成物 |
| `data/` | 設定・カード・ギャラリー。**API トークンは `data/secrets.json` だけ**にあります |
| `models/censor/` | 検閲用モデル |
| `logs/` | バックエンドの記録（不具合を報告するときに添えると助かります） |

★バックアップはこれらのフォルダーだけで足ります。更新はここに触れません。

## 更新

**設定 ▸ 更新**のボタン一つで受け取れます。起動時にも静かに一度確認し、新しい版があれば
通知が出ます。受け取ったあと再起動すると適用されます。差分を取るか全体を取るかは
アプリが判断します。

## 開発

```bash
npm install
npm run tauri dev      # フロント(1420) + バックエンド(8770) + ウィンドウ
```

バックエンドだけを起動するには `python backend/server.py --port 8770`。
依存関係は `backend/requirements.txt` にあります。

## リリース

タグを push するとワークフローが**下書きリリース**を作ります
（`.github/workflows/release.yml`）。

```bash
git tag v3.0.1 && git push origin v3.0.1
```

バージョンは**タグが正本**で、ビルドが `tauri.conf.json`・`package.json` をその値に
合わせます。ビルドが通るかだけ確かめたいときは Actions から手動で実行します。その経路では
リリースを作らず、成果物だけがアップロードされます。

アップロードされる資産は三つで、**アプリの自動更新はこの三つを見ます**
（`backend/update.py`）。

| 資産 | 中身 |
|---|---|
| `PeroPix-<バージョン>-win64.zip` | 全体（約 130MB — Python と検閲モデルまで） |
| `patch-<バージョン>.zip` | 差分（約 35MB — 実行ファイルと `backend/`）← 通常の更新が取るもの |
| `patch-info.json` | 差分にするか全体にするかの根拠 |

- ★**下書きとして作られます。** 公開して初めて利用者に届きます。そして
  **「プレリリース」として印を付けるとアプリからは見えません** — GitHub の
  `releases/latest` が下書きとプレリリースを飛ばすためです。裏を返せば、プレリリースは
  安全に作れます。
- ★`backend/requirements.txt` や `models/censor` が変わった版はワークフローが
  `requires_full` として印を付け、アプリが自動で全体を取ります。**利用者には尋ねません** —
  見えるのはダウンロード量だけです。

## 検閲モデル

`models/censor/*.onnx` を置くとアプリが一覧に出します。既定は**軽いほう**です。
リポジトリには 40MB のものだけが入っています — 239MB のものは GitHub のファイル上限
(100MB) を超えるため、別に置いて使います。
